## Work items

### A. Bugs Azeem flagged

#### A1. Article submit fails silently
- **Symptom**: Azeem tried to submit a new article several times. Form didn't react. No visible error.
- **Suspected cause**: `src/app/admin/articles/new/form.tsx:68` swallows the error from `createArticle` with `catch {}` and only resets `saving`. The server-side `createArticle` likely throws because `Article.oldId` is `@unique` and the form does not set it, so MySQL rejects on the unique constraint, or another required FK is missing.
- **Fix**:
  - Surface the actual error message from `createArticle` in a callout below the buttons.
  - In `actions.ts createArticle`, set `oldId` to `MAX(oldId) + 1` for new rows, OR make `oldId` nullable for net-new content and add a partial unique index (legacy rows keep their MSSQL id, new rows leave it null).
  - Validate required FKs (topic, writer) exist before insert; return a clean error if not.

#### A2. "Display on Site" toggle has no effect for new articles
- **Symptom**: Azeem created an article, flipped the display toggle on, refreshed the public site, article doesn't show.
- **Suspected cause**: the create form has no Issue picker. The new article has no row in `ArticleIssueLink`. `getArticlesForIssue` only returns rows joined through that table. So the article is "saved" but unattached, and toggling display does nothing because no issue page lists it.
- **Fix**:
  - Add a required Issue dropdown to the create form (matches the decision above).
  - On create, also write the `ArticleIssueLink` row.
  - Toggle action runs `revalidatePath` for `/`, `/issues/[id]`, and `/articles/[slug]`.

#### A3. White / dotted vertical line on Word-pasted articles
- **Symptom**: a vertical rule appears beside paragraphs that were pasted from Word.
- **Suspected cause**: Word ships inline `border-left`, `mso-*` styles, and `<o:p>` tags. Either an inline style is drawing it, or a CSS rule in `article-content` is matching one of Word's leftover class names.
- **Fix**:
  - Sanitize on paste (handled cleanly by Tiptap's `transformPastedHTML` once C1 lands).
  - Sweep `globals.css` and article CSS for any selector that draws a left border on classes Word emits.
  - Backfill: write a one-shot script that runs through existing `bodyHtml` rows, strips `mso-*` style fragments, `<o:p>` tags, and inline `border*` declarations, and updates the row. Dry-run mode required, diff written to a log file before the UPDATE runs.

#### A4. "0" rendering in the article admin list
- **Symptom**: a numeric column shows `0` where a label was expected.
- **Suspected cause**: Issue # column for articles without an `ArticleIssueLink`. After A2 every article has a link, but legacy rows may still be unattached.
- **Fix**: render an em-dash placeholder for unattached articles; long-term, surface an "Unattached" badge so admins can find and link them.

### C. Editor upgrade (Tiptap migration)

The current editor at `src/app/admin/_components/html-editor.tsx` is a `contentEditable` div using `document.execCommand`, which has been deprecated in browsers for years. Hashaam asked for Notion-style slash commands; Azeem asked for in-line image upload and tables. Tiptap solves all three plus the Word-paste bug. Decided: migrate.

#### C1. Tiptap with legacy-safe schema
- Install `@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit`, `@tiptap/extension-table`, `@tiptap/extension-image`, `@tiptap/extension-link`.
- Build a custom schema that preserves the legacy CSS classes the seed script imported:
  - `FootNote` and `FootNoteLink` as a `Footnote` node (block) and `FootnoteRef` mark (inline), each serialized with the exact class names so existing CSS keeps working.
  - `ArabicInLineText` as a custom inline mark.
  - `EnglishQuote` as a custom inline mark.
- Provide a `transformPastedHTML` step that strips Word residue: `<o:p>`, `mso-*` styles, inline `border*`, empty wrapping spans, `class="MsoNormal"`.
- Add a slash-command popover with H1, H2, H3, blockquote, bulleted list, numbered list, table, image, paragraph. Same set as today plus image and table.
- Round-trip test before merging. See section E below.

#### C2. Inline image upload
- New endpoint `POST /api/upload-image` (D3 below).
- Tiptap image button hits it, inserts the returned URL as a plain `<img>` in the body.
- Drag-and-drop image into editor: same endpoint.

#### C3. Tables
- Tiptap table extension. No custom markup.
- Default toolbar buttons: insert row above/below, insert column left/right, delete row/column, delete table.
- The Hadith tables Shehzad sahib produces in Word will paste in as tables once C1's sanitizer is in place.

#### C4. Paste-from-Word cleanup
- Handled by `transformPastedHTML` in C1.

### D. Uploads infrastructure (new section, replaces the broken books upload)

#### D1. Prisma `Upload` model

Added locally, awaiting review:

```prisma
model Upload {
  id           Int      @id @default(autoincrement())
  fileName     String   @map("file_name") @db.VarChar(255)
  originalName String   @map("original_name") @db.VarChar(255)
  mimeType     String   @map("mime_type") @db.VarChar(120)
  sizeBytes    Int      @map("size_bytes")
  relPath      String   @unique @map("rel_path") @db.VarChar(500)
  uploadedById String   @map("uploaded_by_id")
  entityType   String?  @map("entity_type") @db.VarChar(40)
  entityId     Int?     @map("entity_id")
  createdAt    DateTime @default(now()) @map("created_at")

  uploadedBy User @relation(fields: [uploadedById], references: [id])

  @@index([entityType, entityId])
  @@index([uploadedById])
  @@map("uploads")
}
```

Plus a back-relation `uploads Upload[]` on `User`.

`relPath` is the path inside `${UPLOAD_DIR}`, e.g. `articles/2026/06/foo-1717000000000.jpg`. `entityType` + `entityId` are optional so an upload can be created before the entity exists (image inserted into a draft article that hasn't been saved yet) and linked retroactively.

#### D3. `POST /api/upload-image` (new)
- Auth-gated (`canEditContent`).
- Multipart form: one file field.
- Allowed MIME: `image/png`, `image/jpeg`, `image/webp`, `image/gif`. SVG rejected.
- Max size: 10 MB.
- Writes to `${UPLOAD_DIR}/articles/{yyyy}/{mm}/{slugified-original}-{timestamp}.{ext}`.
- Inserts an `Upload` row.
- Returns `{ url: "/files/articles/2026/06/foo-1717000000000.jpg", uploadId }`.

#### D4. `GET /files/[...path]` (new)
- Reads from `${UPLOAD_DIR}/{path}`.
- Path traversal guard: resolve the absolute path, verify it's still inside `UPLOAD_DIR`. Reject otherwise.
- Streams the file. Sets `Content-Type` from the stored `mimeType`. Sets `Cache-Control: public, max-age=31536000, immutable` since URLs include a timestamp.
- Returns 404 if the file is missing or the DB row is gone.

#### D5. Refactor existing `POST /api/upload` (books)
- Today it writes to `public/books/`. After deploy that folder is empty, so no books actually work. This route is broken and currently used by `Book.fileName` and `queries.ts:783` (`/ebooks/${b.fileName}`).
- Refactor to write to `${UPLOAD_DIR}/books/` and return `{ url: "/files/books/X" }`.
- Insert an `Upload` row with `entityType: "book"`, `entityId` filled in by the form once the book row is created (or null on upload, updated on book save).
- Update `getAllEbooks` in `src/lib/queries.ts` to return `fileUrl: "/files/books/${b.fileName}"`.
- The same applies to ebook cover images at `/ebooks/${slug}-cover.jpg` (queries.ts:782). Today these references are dead. Either remove them, hide the cover image, or add an upload field for covers. Recommend: add cover upload field on book form, store the cover as an Upload row.

#### D6. Legacy image references in article body HTML
- Many legacy articles contain `<img src="http://www.monthly-renaissance.com/images/artijul09.gif">` (absolute, hot-linked to the old GoDaddy server) and `<img src="QurExg_files/image001.gif">` (relative paths that don't resolve on the new site).
- Three choices, pick one before the editor migration:
  - **Pull the images from the old server** into `~/persistent/uploads/legacy/` and rewrite URLs during seed. Highest fidelity. Requires GoDaddy access.
  - **Strip the broken tags during seed**. Cleanest. Loses Shehzad sahib's Hadith tables permanently.

### E. Legacy data audit for Tiptap migration (Hashaam's specific concern)

Before flipping the editor over, run this audit so Tiptap doesn't quietly mangle 35 years of content:

1. Pull the 20 most complex legacy article bodies from `data/exports/content.json`. Pick across categories: long-form scholarship, Q&A, articles with Arabic spans, articles with footnotes, articles with image tables, articles with `EnglishQuote` blocks.
2. For each, render through the new Tiptap schema and serialize back to HTML.
3. Diff the input vs output. Any classes lost, any tags collapsed, any styling changed: log it.
4. Iterate on the Tiptap schema until the diff is empty for the sample set.
5. Run the same script across the whole `articles` table as a final sweep. Any article that round-trips with diffs gets flagged in a report for manual review before the cut-over.

The success criterion for the migration: an article opened in the new editor, saved without changes, produces a byte-identical `bodyHtml` row.

## Deploy / migration mechanics

Every change in this plan ships through Hostinger's existing git pipeline. The two non-standard steps:

1. **Adding the `Upload` table to production**: there is no Prisma migrations folder in this repo, so this team uses `prisma db push`. After the schema change deploys, run `prisma db push` against production once:
   ```sh
   ssh renaissance-hostinger
   cd ~/domains/skyblue-dotterel-856715.hostingersite.com/nodejs
   /opt/alt/alt-nodejs22/root/bin/node node_modules/prisma/build/index.js db push
   touch tmp/restart.txt
   ```
2. **Adding `UPLOAD_DIR` to hPanel**: log into hPanel, Node.js Application, Environment Variables, add `UPLOAD_DIR = /home/u323192505/persistent/uploads`. The next deploy will write it into `.env` automatically.

After both steps the upload route works. Before either step the upload route returns 500.
